# Windows 构建链路开发自检

这是开发自检，不是 QA 平台覆盖用例，也不加入普通四组默认清单。复用正式 CLI、四组文件加载、计划校验、UI 适配器、任务观察和 HTML 报告，不修改 SDK、引擎设置或用户工程。

执行前保存并正常退出其他 PinK 实例。使用当前已能正常构建的 custom 引擎和 Node.js 24+，在 `tools/build-ui` 运行：

```powershell
npm run build
node dist/developer-selfcheck.js --pink '<指定版本的 PinK.exe 或安装目录>'
```

每次在 `PinK-Test/results/developer-selfcheck-*/project` 创建独立工程，不复制原工程的偏好、缓存、账号和材料。工程仅含一个无用户脚本的场景；样本由 `l10n_007/assets/scene.scene` 派生，移除环境贴图引用并关闭天空盒，不依赖原工程外部资源。场景与 meta 是自检材料，不是通过证据。

两个用例在同一组串行配置提交（上限两项）：

1. `developer.failure.web-desktop`：构建目录 `project://selfcheck-output-blocker/build`。`selfcheck-output-blocker` 是自检入口创建的普通文件；预期 UI 和任务参数一致，真实任务因无法在文件下面创建目录而失败。
2. `developer.failure.web-desktop.variant-1`：使用相同场景和公共配置，构建目录改为 `project://build`；预期任务成功，并完成终态参数及成功卡片核对。

自检入口要求观察到第一项失败终态后，第二项才提交。两项任务 ID 必须不同，失败诊断必须包含故障路径与目录创建错误，报告须统计一失败、一通过。有截图时核对真实文件和链接；没有时必须在原结果和报告中明确说明原因。沿用现有四组的隐私规则，不为自检放开截图。计划过期、配置未就绪、未形成真实失败任务、正常用例失败或报告缺失均不能算自检通过；不自动重试。

正式 CLI 的退出码仍为 1，`result.json/report.html` 保留真实的一失败、一通过。只有这些事实符合开发自检预期，外层自检命令才返回 0；不把失败业务用例改写为 passed。日志与全部原始证据保留在本次目录。故障文件保留，无需损坏/恢复脚本，不检查产物内容或运行游戏。

本入口只覆盖可控真实失败、失败后继续和报告闭环；其他输入错误、UI 回读不一致和连接中断不据此宣称已验收。

可以对同一次原始结果做只读复核，不触发构建或改写报告：

```powershell
node dist/developer-selfcheck.js --verify-result '<本次execution/时间目录/result.json>'
```

只读复核确认原任务和报告事实，不补记一次真实构建，也不重新证明当前环境仍可启动。

## 三类参数不一致自检

默认 ENOTDIR 自检保持原入口。本模式仍调用正式 CLI，不引入第二套执行器，不修改 SDK、引擎设置、PinK 任务文件、参数比较器或原始结果判定。

```powershell
# 五个新用例，最多两项一组；新建独立工程时须先正常退出其他 PinK
node dist/developer-selfcheck.js --mismatches --pink '<PinK.exe 或安装目录>'
# 仅补验尚未通过的终态场景与必要正常对照
node dist/developer-selfcheck.js --mismatch-terminal-only --pink '<PinK.exe 或安装目录>'
# 只读复核该模式结果，不连接 PinK、不触发构建
node dist/developer-selfcheck.js --verify-mismatches '<execution/时间目录/result.json>'
```

已经打开本工具创建的独立工程时，可显式加 `--project '<results 内的独立自检工程>'` 复用，不切换用户工程。入口检查工程路径、专用 package 身份及场景内容，拒绝普通工程；正常执行仍核对程序、工程和计划。全局/工程设置及场景前后哈希校验，不自动覆盖文件恢复。

| 顺序 | 自检内容                                             | 预期                                                                                    |
| ---- | ---------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 1    | UI Debug 目标为 true，使用真实 UI 输入将其改为 false | 正式最终回读检查报错，本项不提交；关闭配置后后项重新设置并确认目标                      |
| 2    | UI 差异后的正常对照                                  | 完成 UI、任务参数、任务成功及成功卡片核对                                               |
| 3    | 入队时，把任务观察副本中的 Debug 从 true 改为 false  | 真实任务保持 true；正式入队比较器报错，唯一任务继续收集到终态，失败不被后续实际成功覆盖 |
| 4    | 入队检查保持真实值，终态收集前只改变观察副本的 Debug | 入队先通过，终态比较报错；收集/清理完成后进入下一组                                     |
| 5    | 跨组正常对照                                         | 失败组已收尾，后组仍完成正常构建和核对                                                  |

UI 项是真实界面状态变化；两项任务参数差异是**真实 PinK 任务上的受控观察夹具**，只在开发子进程通过 Node `--import` 加载，对返回快照做副本转换。比较、任务关联、收尾和报告均使用正式实现。不是 PinK 产品真的丢参数，也不是预写失败 JSON 或替换断言结果。夹具清单及 `injections.jsonl` 记录字段、前后值、来源、阶段和任务 ID；不进入 QA 四组默认用例及共享输入协议。普通运行不加载夹具。

正常完整自检预期原报告三失败、两通过，命令按预期事实判定；终态定向模式仅两个新用例，原报告一失败、一通过。同组任务可能在前项被终态判定之前已提交；该模式验证错误后继续收集后项，跨组继续另由完整模式的组边界证据证明。状态不明时停止、超时、断连、恢复失败仍是后续自检范围，不据此记通过。

## 提交未能唯一确认自检

这是共享提交链路的开发自检，只用 web-desktop，不复制到 18 个平台。每种场景是一次独立的正式 CLI 运行，包含故障载体和应保持未执行的哨兵。每组最多两项，故障后本次 CLI 必须停止提交，不自动再点构建；三种独立场景的先后执行不属于同一次提交的自动重试。

```powershell
# 三种新场景；也可用 none、multiple 或 response 定向执行未通过项
node dist/developer-selfcheck.js --submission-ambiguity all --pink '<PinK.exe 或安装目录>'
# 可加 --project '<本工具 results 内、身份与场景未变的独立工程>' 复用已有实例
# 仅复核已有 JSON、报告、点击记录和只读补核，不启动/连接或构建
node dist/developer-selfcheck.js --verify-submission '<某场景 execution/时间目录/result.json>'
```

| 场景                     | 受控触发与证据上限                                                                       | 正式执行器必须做到                                                     |
| ------------------------ | ---------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| none：零个匹配           | 真实点击一次，在自检子进程的观察副本中隐藏该任务；不是证明产品根本没创建任务             | 等待唯一任务关联到上限后报错；保留关联不明，不重试，不执行哨兵         |
| multiple：多个匹配       | 真实只创建一项，在观察副本增加带 `developer-synthetic:` 标记的候选；不创建第二个产品任务 | 立即拒绝任意选中，错误包含候选 ID；停止后续提交，不重试                |
| response：点击后响应不明 | 原 UI 点击实际执行后，自检调用返回层抛出受控错误；不是破坏网络或 SDK                     | 即使尚未收到任务返回，也按提交可能已生效处理；不重新点击，停止后续提交 |

夹具仍仅通过开发子进程的 Node `--import` 加载，产品任务文件、SDK、比较/关联逻辑及原始结果结论不被替换。`actions.jsonl` 分别记录构建尝试、真实点击送达和夹具动作。第二次点击尝试会被开发保护阻止，同时导致自检失败，不能靠保护把“无重试”伪装为通过。

正式执行结束后三项报告各应为一失败、零通过、一个未执行；错误停在 submit，任务 ID 保持“未关联”，不能把任一候选写成本次唯一任务。原结果的 `taskMayStillBeRunning` 表示当时未确认收尾，HTML 显示“已尝试提交，但任务关联或收尾尚未确认，可能仍在运行”。不自动取消、移除或重建。

外层只读补核使用同一已运行 PinK 的真实观察器，重新核对程序和工程身份，确认每场景实际只有一个任务、哨兵没有任务，并等真实任务成功收尾后才进入下一个独立场景。不启动/重启 PinK，不提交额外构建。`reconciliation.json` 绑定原结果 SHA-256，单列真实任务 ID 和终态；不改写原始 JSON、不把关联不明的用例改成通过。若不能确认收尾，自检失败并停止，不继续下一场景。
