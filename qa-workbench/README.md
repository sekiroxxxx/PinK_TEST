## 标准对象、配置项与候选值接入（2026-11-02）

正式画布的“测试对象与配置项”按对象、配置项展开，可新增并编辑目标的卡片名称、配置页标题、分类、控件类型、定位及就绪范围。表单读取执行侧 `targetsSchema`，仍写回原 `targets`，不注册产品平台、不改变执行合同。

组合编排提供“新建操作链路”，可选已有或自行声明的对象，再按工具能力描述添加平台探查、字段探查、候选读取与选择、独立核验和收尾。步骤中的字段提示包含当前对象声明的配置项，其他平台的专属项不混入提示；候选按精确标签或有类型的机器值填写，不被前端固定选项封锁。动作依赖、目标匹配和恢复仍由模块校验。

新增对象或字段描述只适用于配置检查，不提交构建、不打包；保存、计划和真实页面验收分别确认。已注册插件或字段别名不能作为产品新增平台／字段已实测的证明；没有真实可见样本时保留该证据缺口。

初轮独立 QA 发现：平台用例无条件要求收尾打开、关闭配置页，纯缺失探查无法保存；Source Map 的实际候选含布尔值，文本枚举描述读取受阻。原受阻结果保留，不补开不存在页面或强转候选来绕过校验。

随后 QA 在网页走通现有 `name` 字段的外部描述、保存、真实计划、修改与独立预期回读、原值恢复和刷新查看；它不代表产品新增字段已验收。引用候选已按阶段、序号和自定义名称区分，刷新后原引用保持不变。`mainBundleCompressionType` 的只读候选检查则因弹层无法安全清理而停止，后续选择、回读、恢复及测试字段别名映射均未验证；故障截图中的弹层仍打开，当前窗口状态未确认。两轮均未尝试或提交构建、任务数为零，既有受阻记录和草稿保留。

经用户批准，执行侧已通用修复三处问题：纯 `platform.probe` 与对应断言允许空收尾；混合枚举使用 `kind:"scalar"`、`control:"enum"` 和明确的 `valueKinds`；清理在确认控件、受控列表和焦点后发送一次 Escape，并核对列表关闭及值未变。前端从新 `targetsSchema` 显示单一类型／混合类型分支，嵌套枚举参与分支识别，机器值类型保持原样。执行侧定向离线检查及前端类型、格式检查通过；该阶段 QA 已确认原平台缺失草稿可保存，后续真实执行复查见下方结果，离线检查不作为实机通过依据。

后续 QA 已确认纯缺失探查及混合候选读取真实通过。候选断言曾因 `candidate.by` 缺失无法保存：页面显示了默认匹配方式，却没有写入参数。现按描述补全缺失且唯一确定的固定常量，填写时及保存前使用同一规则；显式设置、独立预期、冲突值及未知字段保持原样，由模块继续校验。执行侧错误返回具体字段路径和属性名，前端定位到对应参数区域。

同一原草稿未重填即保存成功，两处候选匹配均写入 `by:"value"`，8 个主步骤及原收尾保留。独立 QA 仅补测该链路：实际选择字符串 `inline`、回读与独立预期一致，恢复及关闭配置页通过，刷新后记录和报告仍可打开；无构建尝试、提交或任务。恢复值以执行器严格相等核验为依据，报告未公开具体原值。本轮连接约 82 秒、平台探查观察为“未确定”但未断言存在，均保留为观察项，不据此外推真实新增平台已验收。

## 本机存储更新（2026-10-30）

网页正式记录、附件和内容草稿使用 IndexedDB，事务提交成功后才返回保存成功；记录版本检查与写入处于同一事务。Electron 正式记录继续保存为 `workbench.json`，按最终 UTF-8 文件大小统一执行 32 MiB 读写限制；Electron 草稿也使用独立于主记录的 IndexedDB。两端和不同网页 origin 的数据保持隔离。

本轮按用户批准重置开发数据基线：网页新库首次初始化只从旧记录带入可识别的完整内置用例（`内置用例` / `共享合同原生用例` 来源），不迁移旧测试输入、个人试验用例或 localStorage 草稿。旧键不再参与新记录和草稿恢复；官方用例源文件、原生执行格式、文档哈希和已有执行报告目录均不改动。更新后需完整刷新网页。

用例编辑的内容与位置分开保存；切换节点只更新位置，不重写整份内容草稿。草稿写入、清除和撤销按 key 排序，过时的待写内容可由较新输入替代；保存不会清掉期间新增的内容。纯位置存储失败不冒充内容未保存。旧测试数据不做兼容迁移或自动回灌；现有备份入口继续使用原 JSON 合同。

本批代码检查与独立 QA 体验分别记录，存储更新不代表自动化执行、构建或 Electron 试用包已重新验收。

## 网页真实联调（2026-10-27）

在本目录运行 `npm run dev:web:live`，打开 `http://127.0.0.1:5187/`。此命令编译宿主代码、启动仅监听回环地址的本机开发服务，并复用已运行的本工程 Vite；没有运行 Vite 时自行启动。它不打包 Electron，也不显示额外工作台窗口。普通 `npm run dev:web` 在没有本机服务时仍可模拟，启动服务后刷新网页即可接入。自动化入口和准备页显示当前可用的运行方式。

网页通过同源 Vite 转接访问现有宿主接口：选择程序/工程、启动所选目标、保存设置、预览真实计划、启动和安全停止不提交构建的配置检查，以及读取进度、结果和报告。执行、恢复及构建拦截继续由原 `PinkBuildExecutor` 和独立工具负责。前端没有 shell、通用命令或真实构建入口。原生文件选择器由隐藏宿主承接，选择目录不会上传文件。

**数据分开保存：**浏览器的个人记录、挂载用例、附件、备忘录和草稿保存在当前 origin 的 IndexedDB（开发数据基线见上节），不会导入或覆盖桌面个人记录；JSON 备份格式保持原合同。本机服务默认使用工作区 `work/web-dev-data` 保存设置，真实输出默认在其中的 `automation`，可从设置修改。可用 `QA_DATA_DIR` 指定服务数据目录。浏览器 JSON 备份不包含这些本机输出。`localhost` 与 `127.0.0.1` 的浏览器个人存储也各自独立。

服务只在未打包的开发模式启用，随机端口和私有凭据保存在工作区 `work/web-dev-service/connection.json`，不发送到浏览器或作为 Vite 静态文件开放。转接只接受本机工作台同源请求和明确白名单；浏览器记录保存/恢复不在白名单内。在启动终端按 Ctrl+C 时请求原执行器安全停止，等待恢复和结果落盘后退出；网页关闭不会强杀运行，重开可查看记录。断线会显示错误，不会把真实运行降级为模拟成功。

本批通过网页完成 `FORM-C01.s02.web-desktop` 真实计划及检查：名称写入、回读、断言和恢复通过，`configurationRestored=true`，构建尝试/提交均为 false、任务为 0；原始报告可在网页只读打开。第二轮实际点击网页“停止检查”，显示安全停止中并收尾为 `stopped`；停止在取得原值前生效，未执行写入，恢复步骤如实显示未记录，不能当作修改途中恢复的重复证明（此前接入模块的修改途中恢复证据仍有效）。刷新后两轮记录和报告均可从真实记录重新查看。原生选择器逐步操作和资源管理器实际显示仍需人工界面确认，本批不重试桌面操作工具、不执行真实构建、不打包。

## 历史：V1 交互冻结与试用升级（2026-10-24）

有输入的弹窗按所属项目、环境、测试、检查项或用例来源在本机保留草稿。关闭或按 Esc 不丢弃，使用相同启动方式重启应用后也可继续填写。正式保存成功或主动选择“丢弃草稿”才清除；校验或保存失败不清除。备忘录、项目环境、准备链路、问题、复查、结束整理、本轮检查项编辑及用例编辑弹窗共用这一规则。

草稿保存在当前桌面用户数据下的 localStorage，与正式记录、个人备份和链路导出分开；开发模式与编译后的桌面入口不共用草稿。问题草稿中的证据已经复制到本机，正式保存后才进入问题与个人备份。移除或丢弃草稿不会删除已复制文件，避免误删其他记录引用的证据。本机存储写入失败时会明确提示，当前窗口内仍保留草稿，退出前需正式保存。

开发验证可以用进程环境变量 `QA_DATA_DIR` 指向隔离数据目录、`QA_PINK_TEST_ROOT` 指定默认链路目录；不会更改系统环境变量。
