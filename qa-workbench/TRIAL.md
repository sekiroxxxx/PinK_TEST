# QA 工作台 V1 试用版

版本：1.0.0-beta.2 · Windows x64

解压整个目录后运行 `QA-Workbench.exe`。程序及随附文件需要放在一起；工作台自身不需要另外安装 Node.js。此包未做代码签名或自动更新；如果组织的设备策略阻止运行，请由设备管理员处理。

## 开始使用

1. 选择编辑器 EXE 与测试工程目录。名称从工程描述或目录读取，版本可在开始测试前确认。
2. 最近目标可以直接启动；只换编辑器或只换工程会保留另一项。默认仅启动编辑器。支持目录参数的编辑器可在“启动方式与补充信息”中选择“将工程目录作为启动参数”。启动提示只确认已发出请求，请核对实际打开的版本与工程。
3. 新建测试内容和链路，添加多级分组、操作与检查。步骤可复制、移动与连续添加。编辑中的内容暂存为草稿，保存后才用于新测试。
4. 从“自己测试”开始本轮，逐项反馈，记录问题和证据，追加复查、整理结论。中途返回工作台后可继续原版本和进度。
5. 备忘录独立于链路；试用前后可通过“更多 → 备份与恢复”导出个人备份。

## PinK 真实自动化

1. 准备 PinK 编辑器、测试工程和独立的 PinK-Test 自动化工具目录（需包含已编译的 `tools/build-ui/dist`）。真实自动化使用独立的 Node.js 24 或更新版本；工作台不会自动下载这些工具或 SDK。
2. 从“更多 → 设置”确认自动化工具位置、默认测试输出目录；需要时展开并选择 Node.js 程序位置。PATH 已能找到符合版本的 Node.js 时可留空。
3. 在首页确认待测编辑器和测试工程。进入“自动化测试”，载入工具用例或导入原生用例文件，先查看和按需编辑；保存后的内容才用于新测试。
4. 开始测试前确认本次版本、范围和运行方式。包含构建步骤的链路请选择“真实构建”，生成并核对真实计划后再开始；“真实配置检查”不允许提交构建，“仅模拟进度”不会操作 PinK。
5. 执行时查看正式进度；需要中止时使用“安全停止”，等待已提交任务收尾和配置恢复。不要强杀执行器或在运行中更换测试对象。
6. 结束后查看用例结果、按需展开的配置核验和原始报告。“打开本轮文件夹”可定位本次快照、计划、日志、结果与报告；关闭重开工作台后可从“测试记录”重新查看，不会自动重跑。

首次联调可导入随包的 `试用用例/Web桌面-代表组合.json`，这是本次桌面验收实际执行的原生用例，保留了配置恢复步骤。仍需选择自己的 PinK 编辑器和适用的测试工程；它不是全部平台的用例集。

本次试用验收限定同一个 Web 桌面代表组合。其他平台和用例仍取决于独立工具支持、场景材料、SDK 与本机环境，不能据此视为全平台验收通过。用例文件中的编辑描述不授予新的执行能力，真实操作、断言、恢复和证据仍由独立自动化工具负责。

## 数据与范围

- 本机正式数据继续使用原 `QA Workbench` 用户目录，默认位于 `%APPDATA%\QA Workbench`。不把记录保存到安装目录，不附带开发者的个人数据。
- 保留旧项目、环境、链路、测试记录和附件；已有测试使用自己的内容与版本快照。升级前请保留备份，不用旧版应用重新保存包含新层级的新版数据。
- 原入口的草稿继续可读；开发网页和桌面版使用各自存储，不会自动同步。新步骤草稿按测试内容及链路独立保存。
- 个人内容的动作、字段与条件只是编辑描述；能够保存不表示自动化能够执行。原构建合同接入保留在按需入口，原文与校验由该接入模块负责。
- 自动化已接入真实配置检查和真实构建，同时保留明确标记的模拟模式。新增字段位置记录仅用于草稿恢复，不写入原生执行用例；既有草稿和记录保持兼容。
- 修改默认输出目录只影响新测试，历史和运行中测试保留原位置。个人 JSON 备份不包含独立执行器的本机输出，需要另行保留整个本轮文件夹。
- 浏览器个人数据与桌面个人数据分开保存，不自动同步。独立工具、PinK、Node.js、SDK 和测试工程不包含在本试用包中。通用第三方插件运行时、AI 接口、云同步、多人协作和自动上报 Bug 不属于 V1。
