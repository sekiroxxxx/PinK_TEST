# PinK 测试项目与材料设计草案

本方案服务于已批准的首轮 38 条和条件补测 24 条，供测试组审阅材料组织与可判定性。用例定义以 [首轮回归清单](pink-regression-cases.md) 为准；下表只补材料、初态、观察点和恢复要求，不另维护一套用例。

建议围绕可恢复的共享基础项目组织材料，按初态冲突派生工作副本；工程创建从独立空目录开始，导入输入留在工程外。工程数量取决于配置和依赖能否兼容，不按链路或用例数量复制项目。

修订日期：2026-10-16。本方案已根据用户提供的macOS初步使用汇报补齐材料落地要求；两轮结果、环境和原失败维护于[用例清单](pink-regression-cases.md)，不在此复制结果表。后续按用户授权，仅制作下述四组缺失材料；没有运行测试、修改产品或其他对话的构建工具。

四组材料的实际文件见[材料说明](../README.md)，状态为文件已准备、实机未验证；其余建议名称和数据仍需映射到已有实际文件，不能把设计角色当作已就绪材料。报告已通过部分检查不因新增记录字段而追溯改为失败；尚缺原证据具体值时注明待补，优先从既有记录取值，不为填表重跑。

### 共享基础材料

| 材料组         | 建议组成                                                                                                      | 共用范围与限制                                                                     |

| M-A Agent 材料 | 一个已有业务文件中的小文案修改点、明确不变的玩法/依赖、名称相似但路径不同的定位对照                           | A01–A03；修改点不与 L10N 文本覆盖冲突，单次请求，不扩展复杂多轮                    |
| M-B 构建材料   | 有效 web-desktop 输入、场景入口及输出约定、调试选项观察依据、独立故障内容和修复原件                           | B01–B09；实际任务历史由用例通过面板创建，不预置已完成任务代替操作                  |
| M-N 新建入口   | 独立、确实为空的目录和可用的产品创建入口                                                                      | E03 独立于已有基础项目；不能提前拷入模板、场景或项目清单                           |

A、B 是场景角色，不提前要求两套独立项目。优先让同一对场景承载编辑身份和运行身份；编辑子树与 RuntimeRoot 分开，业务脚本只处理约定的运行对象，不写编辑目标、不自动修复场景。如果现有材料不能可靠隔离这两种职责，再分开场景，不能为了减少文件而掩盖编辑缺陷。

项目内不默认放旧 Creator 测试框架、结果上传代码或 localization-editor 安装依赖。已有 extensions 应按合同和依赖逐项判断，不一概删除。当前 38 条未要求项目扩展加载专项，不能借此新增专项；若已批准用例所需的正常扩展确有依赖，应记录和适配，不能删扩展避错。

### 初态与隔离边界

以下是逻辑状态，不是必须永久维护的独立工程或自定义状态文件。

| 状态                      | 内容                                                                            | 不能提前完成的部分                                                         |
| ------------------------- | ------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| S0 基础干净态             | 项目已初始化，场景已保存，无待审查 Agent 修改；基础资源正确；无活动预览/构建    | 节点创建、编辑、删除、复制和保存决策由用例操作产生                         |
| S1 本地化启用但构建未配置 | 真实 Catalog 和绑定已就绪；本地化构建选项、平台偏好未保存；无可复用历史语言任务 | B04 的首次默认值必须从真实未保存状态读取，不能预写一份“等同默认”的配置冒充 |
| S2 本地化已配置           | 与 S1 相同项目内容；目标、默认、回退选项由 UI 配置并保存                        | B02/B03/B05 中被测的设置及任务提交仍通过面板执行；保存前后状态需区分       |
| S3 故障工作态             | 从健康副本派生，独立故障输入在工程外，健康原件可恢复                            | B07 由被测流程引入/修复故障并提交真实任务，不预填失败记录                  |
| S4 未保存工作态           | 从已保存 A 状态现场修改为 B，保留真实 dirty/undo 状态                           | E04 的未保存状态不能通过磁盘文件预写或 Bridge 伪造                         |
| S5 名称冲突工作态         | 工作目录中已有原资源及引用；同名输入在工程外，保留原件                          | R09 的导入、重命名及冲突处理必须真实发生                                   |
| S6 Agent 待审查态         | 基于干净已有文件，由真实 Agent 单次请求产生差异                                 | 不能提前提供补丁、预改文件或伪造模型回复代替 A01/A02                       |
| S7 空目录态               | 工程目录不存在或已确认独立且为空，产品环境就绪                                  | E03 通过 UI 创建项目、创建场景并首次保存                                   |

S0、S1、S2 可共享资产来源，能否共用工程取决于 L10N 启用是否改变编译、场景绑定及默认构建贡献。建议基础编辑/资源/Agent 使用 S0，L10N 用独立工作副本隔离 S1/S2。若目标包证实启用不干扰其余行为，可共用内容，但不能共享会污染初态的设置。

构建任务、平台偏好、自动保存、浏览器语言存储、Agent 审查状态可能存在于工程外。恢复项目文件不等于恢复全部状态，须把这些前提单独检查。

## 可判定材料

### 场景与运行状态

建议的固定数据只用于让预期可观察，不要求已有素材采用同名结构。

- 场景身份：A 显示“场景 A”，B 显示“场景 B”，保存的不同标识同时可从资源身份核对，避免仅靠相似背景图辨认。
- 编辑目标：普通可见 Sprite，名称、父节点、位置、组件和资源引用均有基准；复制子树含至少两个可区分子节点。
- 多选节点按 E09 使用 A=(10,0,7)、B=(20,0,9)，另有未选 C；C 的位置也明确记录。不要从待测代码计算这些预期。
- 交互：初始计数 0；一次真实点击变为 1；重置回 0。键盘输入使用已知字符串，例如 pink42，回显必须与输入一致，不从固定“输入成功”提示代替。
- 场景切换：真实点击入口 A→B→A，显示对应身份并可继续交互。不能直接调用运行时切换函数代替点击。
- 尺寸适配：材料就绪信息填实际Canvas设计尺寸、锚点/适配规则、宽/窄视口、具体控件及其预期相对位置/可见性和点击后状态。先复用原实测记录；报告只概述通过，没有这些值时标待补，不能凭空规定像素容差，不扩大设备矩阵。
- P06 使用用户手势触发的现成、可持续听辨音频及可见临时对象。页面/对象与声音两个子检查可分两次关闭；先人工确认正在播放，再关闭听辨旧声音终止。截图/普通日志不足以替代；避免关闭前已播完造成假通过，遵守浏览器限制并记录焦点。
- 刷新/重新启动后计数、输入和临时对象恢复约定初态；明确持久化功能除外。计数器由真实事件改变，不能脚本定时自增、自动触发回调或只输出“通过”。
- 编辑保存的观察对象必须来自场景持久化，不由 Runtime 在缺失时自动重建。运行脚本不能自修复测试缺陷。

### 资源与身份

- 原件 R0 与更新件 R1 需要肉眼可辨的内容差异，不能只靠文件名/修改时间。PNG 的透明边、比例、颜色应可检查；替换材料可优先保持尺寸一致以聚焦更新行为。
- 外部导入原件不带与工程现有资源冲突的身份；导入产生目标工程自己的身份。R01 前必须尚未导入，不能预置图标或 meta 冒充导入。
- R02/R10 更新既有资源时保留其 .meta 和身份，先记录直接引用关系；R05 副本独立身份由真实复制产生，不能事先手工改 UUID 来“证明”独立。
- R09 同名输入与原资源内容不同，既有引用的画面能说明是否被意外覆盖；重命名冲突目标与空名称分支各自恢复初态，不绑定具体自动后缀。
- R08 需要同一路径可替换的无效/有效配对；错误原因确定。文本伪装 glTF 是旧样本线索，是否采用取决于目标格式适用性，不默认新增模型专项。
- R06 使用未引用材料，R07 使用已保存场景的直接引用材料；依赖列表有已知正例与无关资源对照。脚本字符串路径不纳入自动引用保持预期。
- 图集、模型、字体只在已选条件项需要时准备整组依赖，不把 .gltf、.plist、.fnt 单独拿出当完整材料。

### 本地化

建议最小用三种语言角色，不先冻结具体 locale：S 为源/回退语言，T 为目标/默认语言，U 为未选对照。实际 locale 从目标插件真实 Catalog 取得，不写不存在的语言标识。

| 条目或配置       | S                        | T                          | U                          | 观察目的                                  |
| ---------------- | ------------------------ | -------------------------- | -------------------------- | ----------------------------------------- |
| 完整文本 Key     | 明显的源语言文本         | 明显不同的目标文本         | 可区分译文                 | B02 默认/切换；B03 完整条目不受回退干扰   |
| 缺译对照 Key     | 明确回退文本             | 有效资源中 Key 不存在      | 不影响主对照               | B03 真正的缺 Key 回退，不能用空字符串冒充 |
| B02/B03 语言选择 | 选中，回退 S             | 选中，默认 T               | 不选且不承担其他依赖       | 目标、默认、回退各自可判断                |
| B04 初始构建状态 | 已有 Catalog，默认源语言 | 已有 Catalog，但构建未配置 | 已有 Catalog，但构建未配置 | 观察首次默认只选 S，不是只有 S 数据可选   |

绑定文本位于稳定节点，启动脚本不传语言覆盖参数，不自动收集、翻译、补 Key 或保存配置；语言切换只响应用户操作。B03 必须确认从已保存 Catalog 到有效产物不会把缺 Key 自动补成空值/源文；若插件自动补齐，记录为材料表达或产品合同缺口，不改编译器、不修改产物来伪造缺译状态。

无有效历史语言偏好是浏览器/运行配置条件，不伪装成 Catalog 文件。用隔离浏览器存储或临时用户环境验证，不清真实用户数据。空字符串语义仍不在 B03 内。初始配置的保存位置按目标插件实际合同确认，本方案不规定隐藏路径或新配置协议。

### Agent

建议让已有业务模块导出一个非本地化的按钮文案，运行场景的实际 Label 消费它。A01 请求把旧文案改成约定新文案，其他计数、场景切换及依赖保持。既检查差异和文件，又通过重新启动运行观察对应 Label；不只依赖脚本打印“已修改”。

A03 的目标与诱饵文件可同名、不同路径，正文和标记明显不同。诱饵放在不参与业务编译/资源扫描的参考区域，避免同名类或声明冲突；仍位于可定位的工作区上下文中。文件位置和排除配置须核实，不默认任何根目录都被引擎忽略。

A02 从原有已保存文件开始，先确认真实请求产生可审查差异再拒绝；没发生修改不算验证拒绝。A03记录可见输入路径/附件、实际改动、诱饵不变及业务结果，不断言模型内部从未读取其他文件。不混用户新编辑，不用复制原件代替拒绝。接受前可能已应用/保存，最终决定结果才是判据；服务/权限阻塞单列。

## 恢复与环境约定

### 恢复方式

| 代号 | 方式                                                                                                 |
| ---- | ---------------------------------------------------------------------------------------------------- |
| R0   | 关闭当前操作上下文，重新从不可变基础材料获得工作副本，确认项目与场景身份；无需每次重装或全量构建     |
| R1   | 同一条内按要求关闭/重开、撤销/重做或保存决策；完成证据后才执行 R0，不能在检查前用恢复动作掩盖失败    |
| R2   | 同步恢复资源内容、.meta、引用及目录；失败/冲突材料保持在工程外；等待真实导入完成                     |
| R3   | 先结束已提交任务，记录实际任务和输出，再隔离任务历史、平台偏好及输出目录；不删除运行中任务和诊断证据 |
| R4   | 恢复 L10N Catalog/绑定/配置，另隔离浏览器语言偏好和相关用户配置；B04 需真未保存配置态                |
| R5   | 保留差异与结果证据，结束/隔离 Agent 会话，恢复已有文件与用户状态；下一条从新的干净请求开始           |

## 影响设计的合同与待核实点

这些是材料能否表达预期的具体问题，不是逐项重新确认基础功能支持，也不要求在设计阶段反复运行产品。

1. E03 的类型和命名：当前来源为目录命名/3d模板，与手册2D选择不同。空目录材料独立，目标macOS按实际入口校准，不预制错误模板。
2. B03 缺Key：目标插件是否在保存/编译时自动补全缺Key，会决定Catalog如何表达真实缺译；空字符串不替代，不能修改产物规避。
3. B04/B05 构建状态归属：哪些平台偏好/任务保存在工程外，需要在执行前明确；复制工程不能保证“未配置”或历史任务隔离。
4. B06报告已通过，但未给实际产物路径/字段及开关目标值。优先取原执行记录补齐材料参数，不凭空冻结特征、不为补表重跑、不追溯改写原通过。
5. B07 失败输入、B08排队、B09取消：致命性与真实可操作窗口需在目标版本校准；不能靠大批量素材或测试钩子虚造状态。
6. P05报告已通过，具体适配/视口参数需从原记录补；P06对象生命周期部分完成，仍缺播放中关闭的人工听辨和持续音频条件，两子检查分开。
7. Agent诱饵不参与编译/资源扫描、修改点确实被运行消费；L10N不覆盖这个文案。编译包含范围和实际模块引用需核实。
8. 条件项中的自动刷新、错误分级、内存阈值、未保存构建、构建中编辑、文件夹重导、实时更新和Agent中断恢复仍保留待定，不因材料设计冻结合同。

工程、扩展和源素材所有权/来源保持可追溯；旧Runtime安装依赖不继承，正常项目扩展不一概删除。当前冻结的是用例编号、材料角色、被测操作不可预置及独立恢复原则；具体文件、locale、工程版本和依赖闭合仍以实机材料为准。

## 审阅建议

优先批准“共享基础内容＋独立工作副本/初态”的组织方式：两个可区分场景角色供编辑、预览和Web共用；工程外资源输入；L10N启用/未配置/已配置状态；独立故障、冲突和Agent工作态；真正空目录用于新建。仅当配置或依赖无法兼容时拆项目，不预定工程数量。

现有图片、音频、资源依赖组和部分UI/事件/构建内容可作原件或适配来源；本轮四组文件已落地，剩余确定性交互组合、更新配对及Agent小修改/定位等材料仍保留设计状态。继续按实际缺口准备，不迁移整个Creator测试工程和框架。

前次修订只更新执行说明与材料缺口；随后用户单独授权准备四组缺失材料，现已落地到 `materials/initial-gaps-2026-10-16`，用例范围及材料角色不扩展。复用已有最小游戏资产/业务和L10N数据格式，只在独立副本新增往返按钮、真实L10N对照与切换、故障/恢复输入、JSON读取入口，并修正源场景已有的一处背景悬空引用；原工程和R07现场保持不变。材料README记录来源、初态、使用路径和macOS接收提示词。只完成文件静态检查，不启动定向补验、重跑、构建、安装插件或自动化；实际执行仍另行授权。
