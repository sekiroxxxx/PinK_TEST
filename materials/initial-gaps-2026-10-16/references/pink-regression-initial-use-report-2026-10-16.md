# PinK 回归测试用例初步使用情况汇报

汇报日期：2026-10-16\
执行平台：macOS，Apple Silicon\
执行期间：2026-10-15 至 2026-10-16

本批用例已完成首轮试用、失败定位和更新环境后的定向复测，可以阶段收尾。用例能够覆盖编辑、保存、预览、构建、资源和 Agent 的主要使用链路，并发现可复现的问题；目前还不能作为一套材料齐全、可独立重复执行的完整回归基线。剩余阻塞应在人工输入或材料到位后按项补验，不建议在相同条件下再完整重跑一轮。

## 三、发现的问题与调查结论

### 仍存在的问题

| 问题 | 影响用例 | 具体表现 | 原因与证据边界 |
| --- | --- | --- | --- |
| 删除前的引用影响列表不完整 | R07 | 删除保存场景使用的 en.png，弹窗仅列 en.png/texture，没有列使用场景 | 首轮实际包和 SDK 调查确认：入口只查询 PNG 主资源的直接使用者；真实依赖为场景→SpriteFrame→texture→PNG，未展开子资源的外部使用者。alpha.36 环境仍复现相同提示，不能归入旧 PreviewPlay 故障 |
| 主动取消构建后显示失败 | B09 | 运行中取消后，任务记录和界面均为 failure/失败；后续独立正常任务成功 | 首轮确认 Host 取消状态会被迟到进度覆盖，Builder 另把 cancelled 映射为 Failed。本轮取消后错误为引擎临时目录 ENOENT，与旧版 is break 不同；现象仍存在，但本轮内部错误链尚不能直接认定完全相同 |

R07 已补充实际确认删除：PNG 和 Meta 被移除，节点及 Sprite 组件保留，场景文件保留原 SpriteFrame UUID，Inspector 显示 Missing。保存关闭重开后，原图片变成紫红色缺失纹理块。该结果符合确认框中“删除会使引用失效”的警告，目前没有发现误删其他内容，**不能把 R07 写成“删除执行失败”**。

删除后旧图片曾继续显示，重开才变成紫红色块，这是一个待调查的刷新现象，尚未作为独立缺陷定案。保存前后另有三处相机 orthoHeight 自动变化，未手动编辑相机，原因未调查；没有将此变化直接归因于资源删除。删除后的测试现场保留，原 PNG 和 Meta 有备份。

### 已恢复或已澄清的情况

- **旧环境编辑故障，影响 E01/E02/E06/E09：** 首轮确认场景事件转发访问未注册 PreviewPlay 服务时抛错，引起重命名反馈、Inspector 同步和批量写入异常。四条用例在本轮环境均通过，当前不再按仍失败项汇报；保留旧环境证据，避免丢失版本兼容信息。
- **B05 输出名追加 -001：** 已确认为新草稿主动避开已有任务或目录的命名策略，不是本次配置持久化丢失。用例已通过，不作为缺陷。
- **P01 曾出现界面引擎配置与实际 Host 不一致：** 已定位到按项目路径复用旧预热 Host，用户要求暂缓。后来重开、确认实际引擎后 P01 通过，不代表预热问题已经修复。本轮没有继续扩展调查。

## 四、剩余阻塞与最小补验条件

阻塞不等于产品失败，也不等于通过。10 条中，4 条缺可靠人工输入，1 条缺音频听辨，5 条缺业务或对照材料。

| 用例 | 已完成部分 | 仍需补充的最小条件与操作 |
| --- | --- | --- |
| E07 移动工具与属性同步 | 属性输入及部分同步已观察；新环境两次轴拖动未形成可靠位移证据 | 人工对可见节点真实拖轴，核对 Inspector；输入明确值、撤销重做、保存重开。当前控制输入限制不能作为移动工具失效的证据 |
| R01 外部图片导入 | 外部 PNG 和可用场景已准备 | 人工 Finder→PinK 资源视图拖入 PNG，再赋 SpriteFrame、保存重开并预览；不以磁盘复制替代 |
| R04 导入目录落点 | UI 创建文件夹已完成 | 在选定目录完成真实导入，核对落点及其他目录未误写；可和 R01 共用一次拖入 |
| R09 同名外部导入 | 非法重命名及空名拒绝分支已通过 | 再向同目录拖入同名 PNG，核对保留两份、UUID 独立、原引用未覆盖；不固定自动后缀 |
| P06 预览生命周期 | 已观察角色、血条、摇杆；关闭再启动新页面恢复首页，无旧对象残留，源场景未改 | 人工确认音频正在播放时关闭，听辨旧声音停止；当前截图和日志不足以代替听辨 |
| P04 运行时场景往返 | 编辑器 A/B 目标选择已由 P03 覆盖 | 一个已有 A→B→A 业务入口的工程，附入口和返回步骤；现有 ghost-shooter 只有 login→fight，不具备完整返回链路 |
| B02 目标语言与切换 | 首轮已验证有效语言、非源默认语言及首次显示 | 使用随包 L10N 的真实运行时切换入口；另有第三语言作为未选排除对照。业务自带旧 i18n 不能替代 |
| B03 缺 Key 回退 | 现有可见文本译文均完整 | 目标语言缺一个可见文本 Key、回退语言有译文，另有完整 Key 对照；缺图片条目或空字符串不替代 |
| B07 构建失败后恢复 | 正常构建及取消后恢复已验证 | 已知会导致构建致命失败的输入及对应恢复材料；面板失败后恢复并提交新任务，运行产物。一般警告或主动取消不替代 |
| R08 无效资源修复 | 其他资源更新和重导链路已通过 | 明确无效资源和同类型有效替换对，观察导入失败、原路径修复及重新使用 |

人工补验可集中安排：一次拖图覆盖 R01/R04，第二次同名拖图补 R09；再补 E07 拖轴及 P06 听音。其余需要四组材料：场景往返工程、L10N 对照工程、致命构建输入恢复对、无效资源修复对，L10N 一组可覆盖 B02/B03。未擅自制作业务脚本或人为造坏输入。

## 五、用例本身需要改进的地方

以下为本次试用提出的修订建议，尚未修改原用例清单。

| 改进项 | 本次暴露的问题 | 建议写入用例的内容 |
| --- | --- | --- |
| 执行前材料就绪表 | 范围清楚，但部分业务条件没有现成材料，执行中才发现无法验收 | 每条列工程路径、入口场景、对象/资源、初值、操作入口、预期画面和恢复材料；执行前一次集中核对 |
| 环境身份与版本矩阵 | 应用、引擎和插件分别变化；界面配置有时不能代表 Host 实际加载版本 | 固定记录实际应用路径、PinK、Host SDK、Builder/L10N 和工程；更换任一项另开结果批次，注明复测范围 |
| 状态与统计口径 | 部分分支完成容易被误当整条通过；不同环境结果容易被合并 | 使用通过、失败、阻塞、未执行；每条记录已完成/未完成检查点和阻塞类别，历史结果与最新结果分列 |
| E01/E06 前置及重开检查 | 同名节点和复制现场容易混淆，单看改名成功不够 | 写明完整路径或 UUID、普通 Paste 的兄弟落点、子树初值；明确场景重开和工程重开，并核对原对象未改 |
| E02 撤销焦点与动作分组 | 输入框撤销与场景撤销不同，逐字符输入可能产生多个记录 | 优先产品菜单；输入结束后回到场景，按用户动作检查，不固定底层记录数量；补“保持选区时 Inspector 立即同步” |
| E07/R01/R04/R09 人工输入 | 控制工具无法可靠完成拖轴、跨窗口拖入，与产品缺陷混淆 | 标明必须真实拖放/拖轴及人工接管步骤；输入未送达单列阻塞，不用文件操作替代被测入口 |
| P06 拆分检查点 | 临时对象、关闭重启、短音频听辨集中在一条，难以同时取证 | 分为页面/对象生命周期和音频终止两个子检查，可分两次关闭；提供可持续听辨的现成音频和业务初始化合同；不推断后台服务必须退出 |
| B02/B03 精确对照数据 | 两种语言齐全不代表能验证排除语言、运行时切换和缺 Key 回退 | 配好第三语言、缺失文本 Key、完整文本 Key、回退译文及可见位置；避免历史偏好或业务脚本覆盖结果 |
| B07/R08 错误与修复材料 | 一般警告、其他任务成功不能证明特定失败后的恢复 | 提供确定的失败输入、首个预期错误和对应恢复文件；同一目标建立失败→恢复→可使用的完整证据 |
| B09 取消合同 | 当前“取消状态正确”过于宽泛，不易判断哪里失败 | 分别检查终态、任务卡文字、分组统计、日志和后续任务；运行中取消和排队取消分别说明覆盖边界，保留迟到进度证据 |
| B05 自动命名 | 只比较输出名容易把主动避冲突误报为配置丢失 | 区分新草稿与历史重建；有任务/目录冲突允许自动后缀，其他配置仍须保留 |
| R07 与确认删除分开 | 引用提示失败容易被描述成删除功能失败 | R07 保持“影响列表+取消保护”；确认删除属于另行授权的补测，分别检查文件、子资源、Missing 引用、重开显示及恢复，不默认要求自动清空 UUID |
| 证据落盘与恢复步骤 | 截图在对话内可见，但交接包缺独立图片；共享副本可能被后续用例改变 | 统一记录前后截图、操作时间、任务 ID、日志和文件差异；能导出时保存截图，不能导出则注明缺口；每条提供恢复点及当前现场状态 |

优先补材料就绪表、环境记录、状态口径和最小操作说明，再考虑扩大覆盖范围。当前无需因为工具拖放受阻而降低产品预期，也不建议为完成统计随意改变测试输入。

## 六、收尾结论与后续安排

本次可以汇报为：**38 条用例已完成首轮试用；原 6 条失败经更新环境复测后，4 条恢复、2 条仍存在；10 条仍需人工或材料补验。测试例初步使用阶段收尾，完整回归验收尚未完成。**

后续只需开展三个动作：按修订建议完善用例执行说明与材料；对 R07、B09 进入缺陷处理并在修复包验证；人工输入和四组材料到位后补完对应阻塞项。代码修复、原用例正文修订和额外条件矩阵均不包含在本次收尾工作中。
