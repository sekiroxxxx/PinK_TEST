# PinK 回归自动化测试项目

面向测试组，围绕双方确认的 PinK 稳定功能回归链路，准备测试工程、业务用例及必要的自动化执行工具。目标是让版本更新后可以重复检查已有功能，及时发现退化。

2026-10-17 的[自动化测试需求基线](docs/pink-automation-requirements-baseline.md)冻结了可扩展公共框架、链路独立运行及首批“基本用例＋构建链路”的目标与边界。技术选型和具体实施批次另行确认，不据此扩大已有开发授权。

已确认采用独立 PinK-Test 的方向，不把 PinK 内部自动化基座设为强制依赖。[第一版框架方案](docs/pink-automation-framework-design.md)以既有构建工具和 E01 编辑链路为样本，说明分层、复用、新增和扩展方式；目前为设计草案，未实现公共框架或 E01 自动化。

当前构建用例以[四组构建用例与 18 平台配置设计](docs/pink-build-combination-design.md)及公共 JSON 为依据，现有四组目录已接入 v2 有序操作执行器。Windows 试用请从[工具准备与唯一入口](tools/build-ui/README.md#windows-v2-试用基线2026-10-26)开始；所选 JSON、材料、计划和运行结果需对应同一轮。当前固化的是源码试用基线，全平台基础验收尚待执行；已知语言限制及未迁移分支保留，不将离线可转换等同实机通过。

## 已确认的设计方向

先确定值得保护的用户链路，再明确检查点及测试材料需求，最后选择执行方式和技术。Creator 用例是业务参考库，不要求逐行迁移或全量覆盖。

链路测试保护用户任务和模块衔接，模块行为视角用于查漏。经过模块不等于验证模块；重要缺口可用必要的短用例补足，或明确保留人工检查。

职责先分清，不提前决定仓库和目录拆分：

| 职责           | 负责内容                                                         |
| -------------- | ---------------------------------------------------------------- |
| 测试项目和材料 | 场景、资源、业务脚本、配置及明确的初始状态                       |
| 业务用例       | 操作步骤、关键检查点、预期结果，以及链路和模块行为的关联         |
| 自动化工具     | 环境准备、产品启动、操作执行、等待、结果比较、证据收集和环境释放 |

旧 L10N 安装依赖不作为新工程的默认前提。涉及 L10N 的已选用例使用对应 PinK 随包插件；相关接入是否正确仍需验证。

## 当前工作边界

链路和用例由测试例整理对话维护，当前位置为上述首轮清单；历史与产品调查不另行维护一套清单，不扩大已确认范围。当前不迁移旧脚本、不修改 PinK、CLI 或插件，不安装旧依赖、不执行旧初始化。公共框架的新需求包含轻量本地执行与结果汇总，不建设云端调度或报告管理平台；本次需求冻结不启动代码实施。

新增设计应能对应已确认的链路或实际使用障碍。记录历史时区分需求记载、代码实现和实际执行；记录 PinK 能力时以用户确认和对应版本的接入证据为准。

当前已实现Windows/web-desktop原配置链路、优先8平台D/A/B/C-local及九项本地选项；实际支持范围与[首批交付定稿](docs/pink-build-ui-automation-design.md#首批交付范围定稿2026-10-19)保持一致。18目标配置页中17页基线已有证据；OpenPaaS已有独立必填项/已有游戏选择模式和普通构建入口；旧通用inspect/exercise仍不进入，不代表平台整体待适配。其余新增平台的构建资格按具体条件核实，材料、远程/Zip、产品全部构建及产物/运行验收分别保留。旧展示阶段仅制作HTML/MD；当前合并验收优化已修改独立工具入口，仍未运行产品构建。

## 运行当前最小构建链路

首次在 `tools/build-ui` 执行 `npm ci`、`npm run build`，需要 Node.js 24+。准备完成后，在本目录执行：

```powershell
.\run-build-ui.ps1 -Pink "C:\Users\Administrator\Downloads\PinK-win32-x64-2610121218-0.0.1.39\PinK.exe" -Project "D:\PinK-test\l10n_007"
```

工具启动PinK时传入指定工程路径；已在 9222 端口运行的匹配实例可直接连接。普通启动实例不会被强制关闭，需先保存并正常退出。`-Project`指定并核对目标工程；连接已有实例时要求该工程已打开，不主动切换其工程。结果保存在 `results/<本轮时间>/result.json`，结束后保留 PinK、任务及输出。

在上面命令后加 `-Profile debug -Platform web-desktop` 可运行单平台调试组合；加 `-Suite debug-priority` 可依次运行 Web 桌面、Web 手机、OPPO、vivo、荣耀、华为快游戏、淘宝及 Facebook。调试模式通过 UI 保存组合配置，结束不自动恢复；未显示的字段记为未覆盖。A 轮单平台加 `-Profile release-a -Platform web-desktop`，8 平台按两项分组加 `-Suite release-a-priority`。B 轮单平台加 `-Profile release-b -Platform web-desktop`，8 平台加 `-Suite release-b-priority`。C本地返回分支用 `-Suite release-c-local-priority`。18目标配置页检查运行 `run-config-ui.ps1` 并传入相同的Pink/Project，默认inspect；加 `-Mode exercise` 执行公共字段真实变化、保存重开和恢复，均不提交构建。完整参数、实际结果和缺口见工具使用说明与构建设计。
