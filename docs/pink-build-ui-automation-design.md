### 异常用例的组织与判定

| 类型         | 目的与位置                                 | 通过条件                                                                                |
| ------------ | ------------------------------------------ | --------------------------------------------------------------------------------------- |

公共异常使用 web-desktop 代表，不复制到 18 个平台；其他平台只补自己的控件、字段合同、环境或服务差异。共享失败处理只验必要分支，不强行让每个平台都构建失败。每组仍最多 2 项，组内逐个配置提交、组间等任务收尾；普通构建不重复保存重开。未要求真实变化的同值回读可以证明目标配置正确，不能证明切换、联动或保存动作已发生。

当前四组构建终点统一要求成功，UI-only 场景通过对应的专属检查判定；预期真实构建失败由[开发自检入口](../tools/build-ui/fixtures/failure-continuation/README.md)判定。仅在用例说明中增加“预期失败”不会让执行器自动获得新断言能力。后续优先复用现有检查，新断言只补必要局部适配，不引入通用步骤语言或另一套框架。

#### 共同初态与恢复

1. 核对程序、工程和目标平台；等配置页字段与阶段区就绪。无法确认就绪时不能把按钮缺席记为通过。
2. 连接/拆分用例在任务空闲时执行；记录完整任务 ID 基线。先记录原串联、独立按钮、禁用/提示，以及名称、场景等非目标配置，再准备各例声明的临时初态。活动状态分支只读观察已有获批任务，不在忙碌时改变串联。
3. 只能通过 UI 连接或拆分来准备初态。记录前不改串联；原关系无法识别或不能恢复时受阻，不写偏好文件或调用阶段执行接口准备条件。
4. 每次只点一个已经唯一确认的连接/拆分控件，等待 UI 稳定再回读。任何中间状态均不得新增任务或误触构建、生成、运行、发布。
5. 结束按原记录恢复串联和被本例改变的配置。要求重开的用例再核对保存结果；恢复按关系与可见行为判定，不要求偏好文件中缺省值和空对象字节相同。自动输出名等派生值按已有联动/避重规则检查，不把合法派生变化误判为用户输入被改动。

父阶段按钮禁用时，其内部拆分图标不能直接点击。恢复可以经启用的连接入口先接到可操作的构建组，再拆分和重建原关系；没有安全 UI 路径则停止，不能点击生成/运行来解锁。串联记录只允许本例已知的原态或转换目标；外部改变关系时停止覆盖。连接/拆分只推进共同 revision，不将非目标字段标成已修改；字段恢复因此只核对本例未修改的名称、场景等，防止重写输入掩盖产品副作用。

本文用 `[[build], [make, run]]` 表示“构建独立、生成与运行连接”，只是预期的可读表示，不是新的执行文件格式。用例对指定转换声明精确初态；当前值已经等于目标时，必须在记录后准备真实起态，否则只算回读，不能算完成连接/拆分覆盖。

### 平台构建记录的复用与总链路安排

一条平台链路可以有多个组合用例，公共 UI 用例可以独立选择，也可引用同次平台执行的任务。选择性执行是用例计划的职责，不另建流程语言，不把公共 UI 专项设为所有平台必过前置。当前普通链路以配置完成的最终回读直接提交；仅显式保存专项关闭重开。任务关联、入队和终态参数始终使用同一份finalConfiguration。

| -------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- | ------------------------ | ---------------------------------------------------------------------------------------- |

| 现存失败记录 E-B 淘宝 task-1792208482431-58                                            | 失败标识、错误/tooltip、失败统计和日志、失败任务入口UI                 | 不需要                   | 保留原失败；旧结果的失败事实不等于新加历史UI检查通过，不重复触发已知SDK失败              |

未来执行计划按以下顺序组合，而非每个UI检查各启动一轮构建：

1. **记录准备**：读指定包/SDK/工程身份、现存历史及可复用结果。现存记录的失效只影响相应UI用例，不推翻历史构建结论；无材料记录为受阻，不能自动重建补材料。
2. **静态公共UI**：先做入口、导航和已有记录的查询/展示用例；配置交互按代表平台和条件差异执行。无效输入只检查校验并恢复合法状态，不提交非法构建。
3. **平台组合链路**：按原组合清单配置、稳定回读，普通用例直接构建；仅保存专项重开。公共和专属字段形成同一最终快照，用于入队参数、终态参数和卡片关联，不能回退使用编辑前初态。
4. **动态历史检查**：组内逐个提交、最多两项在途，同步观察本次任务的高亮/排队/进度；组间等待收尾。耗时的筛选、系统对话框、历史编辑等操作放到组后，避免错过动态窗口或增加配置页负担。
5. **完成后复用**：用本次产生的记录补统计、成功展示、日志/配置等缺口，逐UI用例记录结果。UI检查失败与构建失败分开，同一任务构建成功不能抵消历史UI错误。
6. **任务操作专项**：重建、取消、移除及产品全部构建只在明确专项范围、前提和材料就绪后执行；本次仅设计。生成/运行/发布执行不进入本轮。

每条UI结果至少关联 UI用例ID、平台/组合caseId（适用时）、检查目标、预期/实际、证据时间和任务身份。静态复用注明来源runId/taskId及本次检查时间；重建允许复用taskId，另用点击/执行/完成时间区分执行次数。产品groupId/groupCreatedAt与执行器group分别保留，不用屏幕位置或日期时刻作为唯一身份。敏感项只留脱敏匹配结果，截图也需避免泄露。新结果区分通过、失败、受阻、未执行、不适用；源码可见、未要求及材料未就绪不能变成通过，不改写旧schema3/4文件。

## 工具形态与职责

已实现为独立的 TypeScript 命令行工具，通过 Playwright 的 Chromium 调试连接（CDP）控制真实 PinK 窗口及构建 Webview。QA 提供目标包、工程及测试范围，通过 PowerShell 入口运行，无需依赖 Agent 每轮临场点击。命令、依赖及结果格式见[工具使用说明](../tools/build-ui/README.md)。

工具负责带必要参数启动指定 PinK 打包版、建立连接、等待就绪、打开构建面板、操作控件、读取配置、关联任务、等待结果和保留失败现场。最终运行不要求 PinK 源码；开发时允许查询源码，利用已知平台结构、字段及联动规则，不做盲目点击。

不调用 PinK 内部 UI 自动化基座，不加载 Automation Bridge，不要求 `--enable-smoke-test-driver`；已有实现仅供参考，不搬迁或复制整个 VS Code 测试目录。UI 点击、配置修改和提交构建必须通过真实控件完成；必要的只读取证可以利用目标包实际具备的数据，但不能假定内部 API 对外可调用，更不能以直接写配置或提交任务替代被测 UI。

第一版不建设下载、安装、版本管理、账号、云调度、独立前端或新的通信协议。启动和结果约定尽量与其他回归业务线共用，不另建一套环境管理平台。确需修改宿主、CLI、插件、授权或 CI 时，先说明缺口与范围，另行获批。

## 第一阶段：Windows 单平台可行性验证

### 目标与流程

优先选择 web-desktop，验证以下链路能够由工具连续完成：

**启动指定 PinK → 建立连接 → 核对当前工程 → 等待分类入口可用 → 打开平台配置 → 读取现有 UI 配置 → 点击构建 → 识别本次任务 → 等待并复核构建成功。**

配置读取以控件实际值为准，包含本次提交所需的入口、输出及相关选项；具体字段以目标版本为准。失焦并等待联动完成后重新读取，不把填写动作成功等同于最终值正确。不要求本阶段完成所有字段类型、组合或保存持久化专项。

默认 `existing` 模式保留本阶段的只读配置行为；新增 `debug` 模式在第二阶段经 UI 修改组合字段，见下文。平台打开时 PinK 自身可能计算新的可用输出名称，工具记录实际显示值，不通过改名制造任务归属。

### 完成标准

- 工具启动并连接的是指定打包版和测试工程，而非其他已运行实例。
- 能找到实际构建 Webview，打开目标平台，读取配置并执行必要的 UI 操作。
- 构建由真实按钮点击触发；能明确关联本次提交与对应任务，不能误读旧成功记录。
- 本次任务到达目标版本定义的构建成功状态，保留平台、任务关联依据、提交前 UI 配置和最终状态。
- 失败或超时时，指出停在哪个阶段，尽力保留截图及原始关键错误；不会重复点击提交或自动修环境。

成功只证明这条 UI 构建链路可用。不检查输出文件、产物配置、资源内容或运行结果，也不据此宣布 B01 完整通过。第一阶段不覆盖全部平台、完整选项矩阵、历史重建、排队和取消专项。

### 启动与操作边界

工具启动 PinK 时开启调试端口，预期使用 `--remote-debugging-port=<端口>`；端口选择和连接失败处理在实现时完成。普通启动且未开启端口的实例不作为可直接接入的前提，再执行一次带参数命令也不能视为已给原进程开启端口。

本次可行性验证按用户授权使用原用户环境及现有工程，暂不做隔离，未另行配置 SDK。独立用户数据目录和工程副本属于后续重复运行条件的待定方案，不能作为继续验证的额外前提，也不能把本次结果写成隔离运行通过。源码显示部分 SDK 设置位于用户目录的 `.pink/settings.json`，不随 `--user-data-dir` 自动隔离；后续整理条件时需分别考虑。首次登录、SDK 选择和授权若影响启动，应记录前提，不复制凭据或重置日常环境来绕过问题。

除已明确的OpenPaaS正常按钮口径外，提交前确认未额外选择后续阶段；配置调整只在获准范围通过UI完成。OpenPaaS普通构建内部自动make/upload由产品负责，工具跟踪整项任务结果，不另点阶段按钮，不改SDK；具体边界见组合设计。结束保留任务、日志和输出；停止时说明仍在运行或未恢复的项目，不擅自结束其他实例。

## 第二阶段：公共模式、平台专属与差异覆盖

测试组反馈并经用户确认后，覆盖模型改为 **代表平台覆盖公共模式 + 8 平台各自覆盖专属选项 + 必要联动补测**。R/D 保留为参数模板，默认配置用于记录初态，不把 18×2 固定次数作为完整覆盖标准。字段、分支、已有证据、合并轮次及材料去向统一维护于[完整用例清单](pink-build-combination-design.md#公共模式与-8-平台完整分支清单)，不在本页复制另一套清单。

目标顺序为：**确认平台/材料 → 通过 UI 应用组合 → 联动稳定及最终回读（保存专项重开）→ 单平台提交及任务参数核对 → 历史任务 UI 与构建成功 → 条件满足后验证全部构建分发 → 汇总缺口。** 现有普通链路已直接提交，保存专项独立选择；历史搜索/筛选/折叠和明确统计已有只读专项。当前有优先8平台D/A/B/C-local的单平台及两项分组入口，最终快照与任务参数分别核对；本批同平台多case及九项新增字段用例已分批实包验收，逐项证据见组合设计；其他候选仍有缺口。不点击产品“全部构建”，其余候选与缺材料分支不执行。

### 平台和材料

### 组合及批量入口
